# Decisions

Changes to PLAN.md and to fixed targets are recorded here (PLAN Part G.5, E5).

| Date | Topic | Decision | Why |
|---|---|---|---|
| 2026-11-23 | Test runner | `npm test` runs `unittest discover` over `backend/test_*.py`; no pytest dependency | The existing suite is unittest; avoids a new dependency (C24: no upgrades) |
| 2026-11-23 | Branching for 1A | 1A tasks are built on one branch `feat/research-1a-foundations`, one commit per task | The tasks are tightly coupled (DB ← settings ← model layer ← worker); a PR per commit is still possible |
| 2026-11-23 | Roles not named in B6 | Added `grounding.queries` (A sol), `plan.consolidate` (A astra), `read.reconcile` (A sol, borderline-pair judge) as explicit roles; `adjudicate` / `confirm` resolve at run time from `strongest.{family}` | B8.3a, B8.6 and B8.14 name these models but B6 lists them inside other rows |
| 2026-11-23 | Development models | New `dev` profile: family A = `gpt-5.4-mini`, family B = local Ollama `qwen3-coder:latest` (30B), same ensemble structure as `quality`. Saved as the local active profile. The Ollama structured adapter (planned for M2) is pulled forward. `quality` stays the code default | Your instruction: use GPT-5.4 mini and Ollama for now. Pre-flight warns that this profile is not for real cases (models haven't passed E3; Ollama in critical roles) |
| 2026-11-23 | Probe results (live, no health text) | gpt-5.4-mini: structured output OK; accepts effort none/low/medium/high/xhigh; ~2.5 s. qwen3-coder:latest: structured output OK; no thinking capability; ~36 s on first load | Recorded in `backend/data/research_probes.json` |
| 2026-11-24 | One sentence splitter (1A.7) | User text (B8.1) uses the same splitter as papers, so the B8.14 protections (brackets, abbreviations, initials, decimals) also apply to problem text, answers and notes. Abbreviations like "No." and "p." only protect before a number ("No. It stopped." still splits). Rules are versioned as `SEGMENTER_VERSION` (`seg.v1`), stored with each snapshot | "Dr. Lee said…" in a problem text shouldn't become two segments; one rule set is easier to test (X7) |
| 2026-11-24 | Snapshot numbering (1A.7) | `S{n}` is the section's position in `Details.full_text`, so a skipped section (acknowledgements, contributions, notes) keeps its number and later IDs don't shift if skip rules change. Tables and figures are numbered separately in order of appearance; empty cells get no segment but keep column numbers. Back-matter sections are kept unless a skip rule matches; skipped titles go to `skipped_sections` | Stable IDs; B8.14 skip rules |
| 2026-11-24 | Answer length (1A.7) | An answer segment longer than 2,000 characters is clipped with "…" (the API will also validate length in 1C.4) | B2.1 limit |
| 2026-11-24 | Packing order (1A.7) | Packs run abstract → body sections → figure captions and tables (in their own order), because `Details` doesn't record where a table sits in the text. A table split across packs repeats its heading and header rows; a sentence larger than a pack gets its own pack flagged `oversize`. With `max_packs_per_paper` set, later packs are dropped and coverage is `partial` | B8.14 "packs follow document order"; header rows are needed to read cells |
| 2026-11-24 | Literature flags (1A.8) | `Article.retracted` / `concern` are stored as columns in `literature.db` (migrated). Concern uses only the `...In` / `... in` correction types (spikes X4, X5). `full_text_likely` = a PMCID that isn't marked closed: PubMed doesn't report open access, so a PMCID alone counts there; Unpaywall/OpenAlex PDFs join in M2. `fetch_many` posts 200 IDs per call (X5 passed at 200) | B8.8 flags; avoids flagging the notices instead of the papers |
| 2026-11-24 | MeSH module (1A.9) | `mesh.py` follows the X8 rules: a descriptor UI is looked up directly; else an exact heading search; else a free search accepted only on an entry-term match; else unverified (dropped by the caller). Misses are cached too and retried after 30 days. Tests replay 39 recorded responses for 20 terms in `backend/test_fixtures/mesh/` (MeSH vocabulary only, no keys; re-record with `python -m eval.record_mesh`). The held-out check (X8b) passed at 98% without changing the table | B8.1, C36; X8 caveat resolved |
| 2026-11-24 | RecordTransport fix | Recorded responses drop `Content-Encoding`/`Content-Length`, since the body is stored decoded (a gzip answer broke recording). Regression test in `test_research_mesh.py` | Part G.10 |
| 2026-11-24 | Notes basics (1A.10) | `notes.sqlite3` gains the B3 columns (migrated), `secure_delete`, a unique index on (investigation, kind, artifact_key), list filters (investigation, kind, origin, superseded), `NoteInput.investigation_id`, 200 `literature_ids`, and helpers `create_research_note`, `supersede`, `detach_investigation`, `delete_investigation_notes`. A PUT without `investigation_id` keeps the link (older clients don't send it). Live upsert and "edited AI Note becomes the user's" stay in M2 | B12 M1 scope |
| 2026-11-24 | Doctor and eval runner (1A.10) | `research:doctor` is offline by default (`--probe` sends tiny probe requests); exit 1 on any failure; key values are never printed. `eval/run.py` takes a pipeline factory (`app.research.steps:build_pipeline` from 1C) returning (Pipeline, wait resolvers); modes fake / replay / live, where live always records for replay; cases must be `synthetic: true`; `--compare` diffs status, outcome and E1 per case. Only E1.8 is a real check so far; steps add theirs | Part E, G.3-4 |
